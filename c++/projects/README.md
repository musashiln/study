# 综合项目路线

项目用于把分散知识连接成可运行、可测试、可说明的系统。不要等所有知识学完才做项目；每完成若干阶段，就完成一个对应项目。

## 项目统一结构

建议每个项目使用以下结构：

```text
project_name/
|-- README.md          需求、架构、构建、运行和验收
|-- CMakeLists.txt
|-- include/
|-- src/
|-- tests/
|-- config/            可选
|-- docs/              可选：架构图、协议和测试记录
`-- scripts/           可选：构建、数据生成和自动测试
```

项目 README 至少回答：

- 要解决什么问题，不做什么？
- 输入、输出、约束和异常行为是什么？
- 模块如何划分，数据和控制如何流动？
- 如何构建、运行、测试和复现故障？
- 验收结果、已知限制和下一步改进是什么？

## 递进项目

### P01 - 命令行学生信息与成绩系统

**对应阶段**：01–02

- 函数、结构体、数组/字符串和文件读写
- 输入验证、统计、查询、排序和持久化
- 处理空数据、重复 ID、非法成绩和损坏文件

### P02 - 传感器数据分析器

**对应阶段**：02、04、05

- 使用 STL 读取、过滤、统计和导出传感器数据
- 应用算法、容器、`optional`、`variant`、`chrono`
- 比较不同容器和算法的复杂度与实测性能

### P03 - C++ 日志库

**对应阶段**：03、04、06

- RAII 文件管理、日志级别、时间戳和格式化
- 多文件工程、CMake、单元测试、文档和 CI
- 后续加入线程安全、日志轮转和异步队列

### P04 - 多线程任务队列

**对应阶段**：05–07

- 有界队列、生产者—消费者和优雅退出
- 条件变量、异常传播、停止请求和压力测试
- 使用 ThreadSanitizer 检查数据竞争

### P05 - TCP/UDP 传感器服务

**对应阶段**：02、06、07

- 设计带长度、类型、序号和 CRC 的协议
- 处理 TCP 消息边界或 UDP 丢包
- 支持超时、心跳、断线重连和错误数据

### P06 - ROS 2 传感器系统

**对应阶段**：06–09

- Publisher、Subscriber、Service、Action、参数和 Launch
- 自定义接口、QoS、日志、rosbag 与自动化测试
- RViz 或图表展示数据，能够复现一次故障

### P07 - ROS 2 机器人仿真

**对应阶段**：08–09

二选一：

- **移动机器人**：URDF/Xacro、TF2、差速运动学、里程计、`ros2_control`、SLAM/Nav2。
- **机械臂**：URDF/Xacro、TF2、正逆运动学、`ros2_control`、MoveIt 2。

### P08 - MCU 传感器与通信节点

**对应阶段**：10

- GPIO、定时器、中断、UART、I2C/SPI 和 DMA
- 读取真实或模拟传感器，输出带时间戳的数据帧
- 使用 SWD/JTAG 和逻辑分析工具完成调试记录

### P09 - FreeRTOS 多任务控制器

**对应阶段**：10

- 采集、控制、通信和健康监控任务
- Queue、Mutex、Event、软件定时器和看门狗
- 测量任务栈、控制周期和最坏执行时间

### P10 - ROS 2 与 MCU 联合机器人系统

**对应阶段**：11

- ROS 2 驱动节点或 `ros2_control` Hardware Interface
- MCU 实时采样、PID 控制和安全保护
- UART/CAN 协议、时间同步、心跳、CRC、超时和失联停车
- 故障注入、诊断、rosbag 和端到端性能报告

## 项目验收清单

### 功能

- [ ] 所有必需功能均有可重复的演示步骤
- [ ] 正常、边界、异常和恢复路径均经过验证
- [ ] 输入范围、单位、坐标系和错误语义有文档

### 代码与构建

- [ ] 使用明确的目录结构和 CMake target
- [ ] 开启编译警告且无未处理警告
- [ ] 关键资源使用 RAII，所有权清楚
- [ ] 构建产物与配置密钥未提交

### 测试与质量

- [ ] 核心算法和协议有单元测试
- [ ] 模块交互有集成测试或自动验收脚本
- [ ] 使用 Sanitizer、静态检查或目标平台调试工具检查
- [ ] 性能结论有测量数据支持

### 文档与复盘

- [ ] README 可让另一位开发者独立构建运行
- [ ] 有架构图、接口/协议说明和关键设计选择
- [ ] 记录至少一个真实故障的定位过程
- [ ] 列出已知限制和下一步计划

## 项目推进原则

- 先完成最小可运行版本，再逐步增加异常处理和测试。
- 一次只引入一个主要新技术，避免同时调试过多未知因素。
- 保存测试数据和复现步骤，不用“运行过一次”代替验收。
- 项目代码出现重复或职责混乱时再重构，不为了模式而套模式。
